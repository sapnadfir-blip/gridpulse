-------------------------------------------------------------------

Key finding: On a Cortex-M4 relay, just 99 packets per second of attack
traffic saturates the verification queue and causes 100% deadline violations.
This rate is trivially achievable from any device on the substation LAN.


4. QUEUEING MODEL VALIDATION
-------------------------------
- M/M/1 analytical model validated against discrete-event simulation
- Utilization range tested: rho = 0.1 to 0.99
- Error at high utilization (rho > 0.9): 9-12% (conservative upper bound)
- M/M/1 vs M/D/1 comparison confirms Pollaczek-Khinchine bound:
  M/M/1 mean wait = 2x M/D/1 mean wait at same utilization
- The M/M/1 model is deliberately conservative (overestimates latency)
  to provide a worst-case bound suitable for security analysis


5. DEFENSE COMPARISON (8 APPROACHES)
---------------------------------------
Defense           Layer  GOOSE?  Latency     Max Rate    Effectiveness
No Defense        -      -       -           -           0%
Switch MAC ACL    L2     No      ~0 us       Wire speed  High (but MAC spoofable)
VLAN Isolation    L2     No      ~0 us       Wire speed  Partial (same-VLAN bypass)
Firewall (L3-4)   L3     No      50-200 us   N/A         0% (GOOSE is L2, not IP)
IDS/IPS           L7     Yes     100-500 us  100K-500K   Partial (adds latency)
GOOSE IDS         L7     Yes     ~10 us      ~50K        Detection only (no block)
Rate Limiter      L4     No      ~5 us       ~200K       Partial (userspace)
eBPF/XDP          NIC    Yes     0.1-0.5 us  5M-20M+     Full (pre-verification)

Key insight: Only eBPF/XDP operates before the verification queue,
which is the only point where CIL-DoS can be fully neutralized.


6. DEMO CAPABILITIES
-----------------------
The live demonstration runs a 7-phase scripted narrative:

Phase 0: SYSTEM OVERVIEW          (15s)  Introduction to testbed
Phase 1: BASELINE OPERATION       (30s)  Normal: latency ~2.7ms, all OK
Phase 2: RECONNAISSANCE           (15s)  Attacker probes at 10 pps
Phase 3: CIL-DoS RAMP-UP          (30s)  Ramp 500-15K pps, latency climbs
Phase 4: FULL ATTACK               (30s)  25K pps: latency 52ms (17x deadline)
Phase 5: XDP DEFENSE ACTIVATED     (30s)  Defense on: instant recovery
Phase 6: ATTACKER ESCALATION       (30s)  100K pps: XDP holds, 100% drop

The demo uses a software-emulated testbed with:
- Thread-safe message bus emulating substation Ethernet
- Generic relay profiles (not vendor-specific)
- M/M/1 queueing model driving realistic latency calculations
- Rich terminal dashboard with live metrics

Can be run on any macOS or Linux machine with Python 3.10+.
No special hardware, root access, or network configuration required.

8. WHY THIS MATTERS NOW
--------------------------
IEC 62351 adoption is accelerating worldwide:
- NERC CIP standards increasingly reference IEC 62351
- European TSOs mandating encrypted substation communications
- IEC 62351-6 specifically targets GOOSE message authentication

Every utility deploying IEC 62351-6 introduces this attack surface.
The defense (eBPF/XDP pre-filtering) is deployable today on any
Linux-based relay or gateway. This talk provides both the threat
awareness and the practical defense toolkit.
